# CRAN 1.1 Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every item in `../HyperCast/docs/CRAN_CHECKLIST.md`: HyperTabular's eight open features, its reader contracts, both R surfaces and the CRAN gates, with parity across every binding.

**Architecture:** Behaviour lands once in `rust/src/kernel`, behind new size-prefixed structs and new exports, with every 1.0 export and layout kept. `corpus/` pins each behaviour. Then each binding exposes it through one shared checklist, R gets its reader surface, HyperCast freezes, and the submission evidence is produced from the exact tarballs.

**Tech Stack:** Rust 2024 (`no_std`, no `alloc`, `cargo no-panic`), cbindgen, wasm2go, and each binding's toolchain as `CLAUDE.md`, "Local loop", gives it. R 4.2 floor to R-devel, `R CMD check --as-cran`, `rchk`, valgrind, Docker.

**Spec:** `docs/superpowers/specs/2026-11-05-cran-1-1-gate-design.md`. Every rule and decision (D1–D11) is there. This plan assigns them to tasks and fixes the names.

## Global Constraints

- **Starts only after the Go `-unsafe` plan finishes.** That thread is the only one editing code until then. Run `git fetch` and compare with origin in HyperTabular, HyperCast and the Forge before Task 1.
- **The owner drives git.** No commit, stage, push, tag, dispatch, submission or pin move appears in this plan. Each task ends verified in the working tree.
- HyperCast 1.1 and HyperTabular 1.1 are held together. Nothing is released here.
- The 1.0 exports' names, arguments and layouts stay as they are (narrowed 2026-11-06: what HyperCast answers on a shape is its own, and `12,34` and `0,125`, which 1.0 read as 1234 and 125, are refused now, as is `1,23,456`, which 1.0 read as 123456: no legacy grouping, amended the same day, spec's Constraints). The core stays `no_std`, allocation-free and panic-free, and every memory buffer stays the caller's.
- No export takes more than twelve integer arguments.
- A verification counts only when its negative control fails.
- Benchmark tables are dated, on one machine, with losses printed.
- `include/hypertabular.h`, `go/internal/core/core.go`, `typescript/binding.*`, `php/stubs/` and `r/inst/AUTHORS` are only ever regenerated, by the commands in `CLAUDE.md`, "Never hand-edit".
- A change under `rust/src` that reaches the cdylib means regenerating the Go core before Go's tests.
- HyperCast 1.1.0 isn't on a registry, so HyperTabular uses the out-of-tree overrides in `CLAUDE.md`, "Local loop", and puts `rust/Cargo.lock`'s hypercast entry back afterwards.

### Corpus changes

An existing case's values, verdicts, spans, coordinates, failures and header never change, in either
corpus file. The only permitted change to an existing case is adding the reviewed diagnostic fields
`detail`, `origin` and `problems`. Each task that does so runs this check and explains the enrichment in
its report: load the old file from `git show HEAD:<file>` and the new one, delete those three keys from
both, and compare. The existing cases must be identical, and everything else must be an added case.
Any other difference stops the task, as a behaviour change to explain under `corpus/README.md`.

### Binding suites between tasks

Tasks 3–10 each finish with the Rust suite green, including its corpus replay, which learns each new key
in the task that adds it. Other bindings' replays can fail until their own task in 12–21, only where the
failure is demonstrably caused by a corpus key that binding doesn't support yet. Each such failure is
recorded in the task's report, with the key, until its binding's task resolves it. Any other binding failure
is a regression. Task 20 requires the bindings of Tasks 12–20 to pass, and Task 21, where R lands, is where
every binding's replay and the overall export check must be green together.

## Review Focus

- A chunk ending inside a UTF-16 surrogate pair or a UTF-8 sequence should read the same as one contiguous input. Pinned by `transcode_is_chunk_invariant` in Task 6 and `utf8_validity_is_chunk_invariant` in Task 4.
- A `skip` past the end of the input, or a `header_row` past its last record, should be zero rows and an empty header rather than an error or a hang. Pinned by `skip_past_the_end_reads_nothing` in Task 5.
- A byte order mark before lines being skipped should still be skipped once, and `skip` should count the line it sits on. Pinned by `a_bom_does_not_count_as_a_line` in Task 5.
- `na = ""` on a blank cell should be `Empty` at `origin` `1`, and on a padded cell it should stay `origin` `2`. Pinned by `tokens_meet_blanks_and_padding` in Task 5.
- A range boundary falling inside an ODS repeated row or a sparse XLSX row should deliver exactly the rows and columns inside it, at their absolute coordinates. Pinned by `a_range_cuts_repeated_rows` in Task 7.
